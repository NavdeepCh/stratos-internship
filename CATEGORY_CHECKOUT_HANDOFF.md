# Category storefront upgrade
36 domains per category, five branch filters, search, category-specific roadmap, nine existing price plans. Homepage and deployed Workers unchanged.

Checkout is intentionally fail-closed. Both existing Worker origins must expose GET /capabilities with schemaVersion:2, categories:["short-term","long-term","summer"], and respectively categoryEnrollment:true / categoryCheckout:true. Registration Worker POST /register-category must authenticate verified Firebase email, validate catalog IDs server-side, create an idempotent registration, return registrationId and enrollmentStatus. Free plans confirm without payment. Payment Worker POST /create-order accepts receipt and planId, resolves trusted expected amount from registration and returns order_id, amount (paise), currency, key_id. POST /verify-payment accepts registrationId and Razorpay callback fields, verifies signature, ownership, captured payment, receipt and exact amount and returns paymentVerified:true only on verified capture. Webhook reconciliation and email/PDF dispatch remain backend tasks. Existing Worker hardcodes 100 paise for legacy Instant; do not enable capability flags until upgraded and tested.
