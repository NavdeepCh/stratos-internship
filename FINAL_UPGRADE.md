# LIVE ₹1 payment upgrade
Deploy Pages with existing live credentials and service account. Configure signed Razorpay webhooks for payment.captured, payment.failed, refund.processed. No test flag. All amounts except amountPaidInRupees are paise.
Changes: persisted gateway order before checkout; optimistic order creation lock; reuse existing unpaid order; authoritative recovery via Razorpay; reference and refund amount fields; common verification logic for callback and webhook; retryable webhook failures; persistent browser recovery ID.
Limitations: an interrupted order creation lock requires manual support reconciliation before clearing it; never clear without checking Razorpay. Existing legacy orders without stored gatewayOrderId need manual reconciliation. Failed payment attempt history, refund IDs, automatic notification delivery and verified-email enrollment linking are not implemented. Do not deploy as a complete production system without live integration testing. Registration Worker source was not included in the repository. Existing notification Worker must be deployed separately if changed. Do not grant certificates on payment alone.
Test: create registration, check order ID in Firestore, pay ₹1, check Paid/Verified and references; close browser after payment and check webhook; retry status; process refund and check Refunded; verify cross-user requests fail. Back up Firestore before deployment.
