# Category API contract (not deployed)
The ZIP contains an email-oriented worker.js, not the deployed registration and payment Worker sources. Do not replace the existing live Workers with it. Keep Instant checkout unchanged.
Both Workers must expose GET /category-capabilities returning contractVersion: 2 and plans mapping stable plan IDs to exact integer paise; registration additionally returns activeDomains mapping category IDs to approved domain IDs. Only advertise support after testing and operational approval. Registration POST /register-category takes verified Firebase bearer token, form fields, categoryId, domainId, planId and requestId; returns registrationId, expectedAmountPaise, enrollmentStatus, paymentStatus. Payment POST /create-category-order takes registrationId and returns id, key (public Razorpay key), amount, currency. POST /verify-category-payment takes registrationId and Razorpay callback fields; returns paymentVerified, amountPaidPaise, paymentGatewayStatus. Server must enforce ownership, authoritative prices, idempotency, captured status, signature and currency; free registration must bypass payment. Do not enable capabilities before all checks and email/document services are operational. No real payments or emails were sent.
